# 邏輯構想分析契約

本契約規範如何把一個主題、問題或專案構想整理成 **12 個固定章節**，再交付內容一致的 PDF。所有結論都必須可追溯到輸入、來源、明示假設或待驗證工作；不得用完整敘事掩蓋資料缺口。

## 證據狀態標籤

關鍵事實、數字、因果主張、前提、案例結果與目標值，須在首次出現或其表格列加上一個標籤。敘述同一命題時沿用既有狀態，不必逐句重複。只使用實際存在的狀態類別，不得為了湊齊四類而虛構假設或未知：

| 標籤 | 定義 | 使用規則 |
|---|---|---|
| `[已知]` | 使用者已提供，或有可查核來源支持的資訊 | 附來源、日期或輸入位置；模型記憶本身不算證據 |
| `[假設]` | 為了推論而暫時採用、尚未證實的命題 | 說明影響範圍；不得寫成既成事實 |
| `[未知]` | 對判斷有影響，但目前沒有答案的資訊 | 寫成明確問題，說明缺口會影響哪個決策 |
| `[待驗證]` | 已轉成可執行驗證的命題 | 同時給方法、責任角色、期限或觸發點，以及通過門檻 |

狀態會隨證據更新：`[未知]` 可轉為 `[待驗證]`；取得可靠結果後才能轉為 `[已知]`。同一命題若在不同條件下狀態不同，應拆開標示。

## 12 個固定章節

章節編號、順序與標題固定。資訊不足時仍保留章節，以 `[未知]` 列出缺口，不得刪節、補造內容或用「同上」取代。

### 1. 主題相關資訊

依序包含下列欄位；不得把「尚未提供」默認為「不存在」：

| 區塊 | 必填欄位 |
|---|---|
| 主題識別 | 主題／專案名稱、背景、觸發事件、目前狀態 |
| 決策題 | 一個可回答的核心問句、分析目的、預期支援的決策或行動 |
| 分析範圍 | 納入範圍、排除範圍、時間尺度、適用情境 |
| 條件限制 | 關鍵時點／期限、可用資源、硬限制、可調整條件 |
| 利害關係人概況 | 主要角色、關切、影響及初步權責；完整決策結構留在第 4 節 |
| 資料來源清單 | 來源 ID、資訊或主張、證據狀態、來源／輸入位置、日期／版本、與決策的關聯 |
| 資訊缺口 | 缺口問題、證據狀態、對決策的影響、補證方式、責任角色與期限／觸發點 |

來源清單與資訊缺口分開呈現。只列實際存在的證據狀態；若輸入足夠，不必刻意製造 `[未知]` 或 `[待驗證]`。

### 2. 300 字邏輯構想摘要

- 使用一段連貫文字，依序交代背景、張力、核心問題、主張、主要理由、預期行動及驗證方式。
- 使用單一段落，正文為 **250–350 個可見字元**；標題與 Markdown 標記不計入。CJK 文本忽略換行、縮排等排版空白；以空格分詞的語言先把連續空白正規化為單一空格，保留每個單詞間的單一空格並計入字元數。報告撰寫與 validator 使用相同規則。
- 摘要只壓縮後文章節已有內容，不新增數字、案例、因果或承諾。
- 讀完摘要後，決策者應知道「要決定什麼、建議什麼、為什麼、下一步如何驗證」。

### 3. 重要關鍵字與變數

關鍵字用表格整理；每個變數使用一個獨立欄位區塊，避免 PDF 出現超寬表格：

| 關鍵字欄位 | 要求 |
|---|---|
| 統一名稱 | 全文使用的唯一名稱 |
| 操作型定義 | 可據以判斷是否符合的定義 |
| 近義詞／易混淆詞 | 說明差異，不得互換使用 |
| 本分析採用的用法 | 說明該詞在本題中的具體指涉 |
| 證據狀態／來源 | 定義的依據或本次採用的假設 |

| 變數區塊欄位 | 要求 |
|---|---|
| 名稱 | 與關鍵字及因果鏈一致 |
| 角色 | 投入／活動／輸出／結果／干擾／限制 |
| 定義／單位或尺度 | 包含計算口徑或類別判準 |
| 已知值或範圍 | 無資料時標 `[未知]`，不得造值 |
| 預期方向 | 增加／降低／非單調／方向待驗證 |
| 可觀測方式 | 資料、量測方法或可辨識行為 |
| 證據狀態／來源 | 標籤及可追溯位置 |

- 同一概念全篇使用同一名稱；若需改名，明示對照。
- 不可量化的概念也要定義可辨識的行為或判準。

### 4. 核心決策者或主體

先完整描述決策本身：最終決策者／共同決策機制、待決事項、核心目標、決策權限、可支配資源、限制、誘因、決策時點及不可逆程度。再用角色表列出：

| 角色欄位 | 要求 |
|---|---|
| 角色 | 已知姓名或角色名稱 |
| 與決策的關係 | 最終決策／共同決策／執行／諮詢／否決／受影響 |
| 權限與責任 | 能決定、執行、阻擋或被問責的事項 |
| 受益 | 預期取得的價值或改善 |
| 成本／風險承擔 | 負擔的資源、損失、責任或外部性 |
| 參與時點／方式 | 何時、以何種機制參與 |

明確指出誰是主要受益者、誰承擔主要成本或風險。不可把使用者、決策者、執行者、受益者、風險承擔者與受眾默認為同一人。

### 5. 核心論點（Thesis）

- 先用一句可反駁的陳述句寫出主張：誰應在何種條件下採取何種方向，以取得何種結果。
- 接著逐欄列出主要理由、必要條件、適用邊界、反轉／失效條件，以及每項的證據狀態與來源。
- 另列信心水準（高／中／低或明確量尺）及「信心依據／證據狀態／來源」；信心是對主張的整體評估，不得用肯定語氣掩蓋低信心。
- Thesis 必須直接回答第 1 節的決策題，並與第 9 節及第 12 節 `SCQA > A > PREP > P1/P2` 語意一致。
- 若證據不足，將主張寫成 `[假設]` 或 `[待驗證]`，不得使用確定語氣。

### 6. 關鍵概念、定義與前提邊界

每個核心概念使用一個獨立欄位區塊，逐欄列出：概念 ID／名稱、操作型定義／判定標準、定義來源或本次假設、納入範圍、排除範圍、依賴項、失效條件，以及證據狀態／來源。

另設數值與版本慣例表，逐欄列出：項目、採用慣例（計算口徑、分子／分母、幣別、時區、期間或版本）、來源／理由及證據狀態。沒有數字時只列確實適用的慣例，不得為填表而虛構數值規則；未知者直接標示。

### 7. 因果關係與推論路徑

至少建立一條可檢驗路徑：

`投入／介入 → 作用機制 → 直接輸出 → 中間結果 → 最終結果`

先寫出整體路徑，再把 **每一個箭頭拆成一個獨立欄位區塊**。每個區塊固定包含：連結 ID、原因 → 結果與方向、時序／延遲、作用機制、證據狀態／來源、成立條件／依賴、替代解釋／干擾變數、反證觀察、驗證方法／責任角色／時點。不得用一個區塊概括多個箭頭，或只用一組共通說明取代逐箭頭檢驗。

高品質因果鏈須同時具備可解釋的機制、正確時序、可觀測指標與反證條件。不得由活動直接跳到長期影響；僅有相關性時，使用「相關／伴隨」並標 `[待驗證]`，不可改寫成「導致」。

### 8. 重複考量與潛在衝突

以對照表處理：

- 重複：找出語意相同的主張、變數、行動或指標，指定一個主項，其餘改為交叉引用。
- 衝突：辨識事實、定義、目標、資源、時程、利害關係、證據或因果解釋的矛盾。
- 每項列出影響、目前狀態、解法或所需證據、負責角色與處理時點。
- 無法消解的衝突保留為決策取捨，不得任意選邊或靜默刪除。

### 9. 一句話總結

- 只寫一個完整句子，涵蓋主體、建議方向、可辨識的目標狀態，以及最關鍵理由或條件。
- 不用口號，不加入新資訊；語意須與 Thesis 及 `PREP > P1/P2` 相同。
- 若主張仍待驗證，句中保留對應標籤與條件語氣。

### 10. 分眾解釋

用同一主張產出四個版本；改變細節與詞彙，不改變事實、信心或建議方向：

| 受眾 | 應包含內容 | 表達要求 |
|---|---|---|
| 決策層 | 決策請求、目標價值／結果、所需資源、期限、主要風險、停止或轉向條件 | 結論先行，短而可決策 |
| 管理／專業層 | 作用機制、證據與信心、取捨、依賴、治理責任、指標與例外條件 | 保留定義、推論與證據邊界 |
| 執行層 | 任務、順序、責任人、所需資源、交付物、驗收門檻、升級路徑 | 使用可操作動詞與明確邊界 |
| 一般受眾 | 問題、做法、個人或群體影響、預期時程、如何判斷成效、保障措施 | 少用術語；必要術語立即解釋 |

各版本須能追溯到相同的 Thesis、因果鏈及行動方案。不得為了簡化而把 `[假設]` 說成 `[已知]`。

### 11. 行動方案與驗證指標

每一項行動都必須是一個可獨立執行、量測與決策的單元，逐欄包含：

| 欄位 | 要求 |
|---|---|
| 行動 ID／內容 | 使用明確動詞，描述可完成的工作 |
| 依據 | 連到 Thesis、因果鏈連結 ID 或待驗證命題 |
| 責任人 | 寫角色或已知姓名；未知時標 `[未知]` |
| 期限／優先序 | 日期、期間或觸發條件；說明緊急性、價值與依賴 |
| 依賴／資源 | 前置工作、資料、人力、預算、權限與工具 |
| 交付物／驗收 | 可觀察產出及完成判準 |
| 領先指標 | 指標 ID、定義／公式／單位、方向及資料來源 |
| 結果指標 | 指標 ID、定義／公式／單位、方向及資料來源 |
| 基準值 | 分別對應領先與結果指標；有來源才標 `[已知]`，否則標 `[未知]` |
| 目標／護欄門檻 | 數值或判準、期限及證據狀態 |
| 量測頻率／檢查點 | 測量週期，以及日期或明確事件 |
| 決策規則 | 誰判讀；達標、未達標或護欄失守時的繼續、調整、擴大或停止行動 |

不得為了填表捏造責任人、基準值或目標。假設性目標應標 `[假設]`；已轉成可執行測試的門檻標 `[待驗證]`。若某項行動暫時無法定義有意義的領先或結果指標，須明示缺口與補齊方式，不得填入裝飾性指標。

### 12. 複合模型思維導圖

使用 **Markdown 巢狀項目符號**；不得以 Mermaid、四個平行框架或散文取代。語意與縮排必須遵守下列骨架：

```markdown
- SCQA
  - S｜Situation
  - C｜Complication
  - Q｜Question
  - A｜Answer
    - PREP
      - P1｜Point
      - R｜Reason
        - 金字塔原理（MECE；分類準則：同一分類軸）
          - 核心結論：<實際證據標籤＋直接支撐 Reason 的完整主張>
            - 次級論點 A｜<分類類別>：<實際證據標籤＋可被支持或反駁的主張>
              - 底層事實 A1：<實際證據標籤＋證據、假設、未知或待驗證命題>
            - 次級論點 B｜<分類類別>：<實際證據標籤＋可被支持或反駁的主張>
              - 底層事實 B1：<實際證據標籤＋證據、假設、未知或待驗證命題>
      - E｜Example
        - STAR｜驗證設計
          - S｜Situation
          - T｜Task
          - A｜Action
          - R｜Result
      - P2｜Point
```

模板預設 `STAR｜驗證設計` 位於 `E`；有可查核的過往事件時可整體改為 `STAR｜實證案例`。STAR 位於 `E` 時，STAR 本身即構成 `E` 的實質內容，不另加同層摘要節點。STAR 若移至任一「底層事實」，`E｜Example` 須在同一行寫出非空的代表案例、類比或驗證摘要，但不得再掛第二個 STAR。除此之外 STAR 不得出現在其他層級。實際輸出須以本次內容取代占位文字；關鍵事實、因果主張、門檻與 S/T/A/R 節點依實際證據狀態加標籤，不必為所有非關鍵標題加標籤，也不得為湊齊四類而虛構狀態。

## 框架語意規則

### SCQA

- `S｜Situation`：受眾可接受的現況與共同背景，標示已知及假設。
- `C｜Complication`：造成張力的變化、障礙、缺口或機會；必須由 S 合理引出。
- `Q｜Question`：由 C 產生的一個核心決策問題，不混入答案。
- `A｜Answer`：直接回答 Q；其內容必須是一個完整 PREP 區塊。PREP 不得與 S、C、Q、A 平行。

### PREP

- `P1｜Point`：直接表達 Thesis。
- `R｜Reason`：回答為何主張成立；其論證必須包含金字塔結構。
- `E｜Example`：提供支持理由的例子或驗證設計，不以單一例子代替整體證據。
- `P2｜Point`：重申主張及其決策含義，不新增不同結論。
- PREP 嚴格位於 `SCQA > A`；金字塔嚴格位於 `PREP > R`。

### 金字塔原理與 MECE

- 上層結論須能由下一層完整回答「為什麼／如何成立」；下層事實須能支持直屬論點。
- `核心結論` 與每個 `次級論點` 都是實質主張節點，節點文字必須同時包含可被支持或反駁的主張內容及依證據選用的實際狀態標籤；只寫「策略面」「風險面」等分類名稱不合格。
- 同層論點採同一分類維度，彼此盡量不重疊，合計足以覆蓋上層問題；無法完整覆蓋時明示缺口。
- 在 `金字塔原理（MECE；分類準則：…）` 節點明示該組次級論點共用的分類軸，再檢查重複、遺漏及粒度不一；分類準則不是金字塔的額外子節點。
- 演繹鏈需保證前提可支持結論；歸納組需說明樣本與外推邊界。
- 底層只能是有狀態標籤的事實、數據、假設、未知項或待驗證命題。

### STAR 與歷史證據

- `STAR｜實證案例` 只可用於使用者提供或可由來源查核的過往事件。S、T、A、R 均須有依據；Result 必須是實際觀察結果。
- 不得虛構客戶、組織、日期、行動、數字、引言或成果，也不得把提案寫成已完成案例。
- 缺少可驗證過往證據時，改用 `STAR｜驗證設計`：S 是目前情境，T 是待驗證任務或假說，A 是預定測試，R 是成功門檻或目標結果。
- 驗證設計的 R 不是既成結果，必須標 `[假設]` 或 `[待驗證]`，並與第 11 節的指標、期限及決策規則對應。
- STAR 嚴格位於 `PREP > E` 或 `金字塔 > 底層事實`；不得成為與 SCQA、PREP 或金字塔平行的獨立框架。
- STAR 若移至底層事實，`E｜Example` 仍須保留非空且能支持主張的摘要內容；不得留下空節點、占位符或在兩處重複同一 STAR。

## 一致性與品質檢查

交付前逐項檢查：

- 恰有 12 個編號章節，標題及順序符合本契約；第 2 節字數合規。
- 關鍵事實、數字、前提、因果、案例結果及門檻在首次出現時有正確證據標籤；沒有的狀態類別未被虛構。
- 名詞、數字、單位、時間範圍及主體在各節一致；差異有明確解釋。
- 第 5、9、10、12 節的核心主張一致，並直接回答第 1 節的決策題。
- 每項建議可追溯至理由、因果鏈與證據；每個 `[未知]`／`[待驗證]` 有處理方式或明示不處理的理由。
- 因果鏈沒有跳躍，相關性未被誤寫為因果，替代解釋與反證條件已列出。
- `SCQA > A > PREP > R > 金字塔` 的縮排與語意正確；同層分類通過 MECE 檢查。
